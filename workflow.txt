================================================================================
AGENTIC ML EVALUATION PLATFORM - SYSTEM & EXECUTION WORKFLOW
================================================================================

This document provides a clear, plain-text walkthrough of the entire system 
architecture, data flow, agent decision cycle, and file responsibilities.

The agent dynamically decides which tool to run next based on observing previous results rather than executing a hardcoded sequence.
It maintains explicit state, detects problems autonomously, applies targeted transformations, and stops only when the goal is achieved.

Index:
1)SMOTE:Stands for Synthetic Minority Over-sampling Technique.
It is a technique used in machine learning to handle imbalanced datasets.
2)Accuracy:Proportion of all predictions that are correct.
3)Precision:Proportion of predicted positive cases that are actually positive.
4)Recall:Average of the F1-scores calculated separately for each class.
5)Minority F1:F1-score of the minority class.
6)Macro F1:Average of the F1-scores calculated separately for each class.(2*Precisio*Recall/(Precision+Recall))

2. THE CLOSED-LOOP AGENTIC CYCLE (STEP-BY-STEP FLOW)
================================================================================

The agent is designed as a closed-loop controller around the model and dataset:

   [ START: User Goal e.g. "Evaluate my Iris model and improve if imbalanced" ]
                                      |
                                      v
                        [ STEP 1: Inspect Model ]
           (Framework: Sklearn/PyTorch, Input Shape, Parameters)
                                      |
                                      v
                        [ STEP 2: Inspect Dataset ]
           (Rows, Columns, Feature Types, Target Column, Outliers)
                                      |
                                      v
                     [ STEP 3: Validate Compatibility ]
           (Verify Dataset Feature Count == Model Expected Input)
                                      |
                                      v
                  [ STEP 4: Run Baseline Evaluation on v001 ]
           (Calculates Accuracy, Precision, Recall, Macro F1, Minority F1)
                                      |
                                      v
                    [ STEP 5: Data Quality & Audit Check ]
           (Calculates Missing Values Count, Class Imbalance Ratio)
                                      |
                                      v
                   [ STEP 6: Noise Robustness Benchmark ]
           (Adds 10% Gaussian Noise and Measures Performance Drop %)
                                      |
                                      v
                           { Were Issues Detected? }
                                 /          \
                               /              \
                    [ YES: Imbalance / ]      [ NO: Clean Data ]
                    [   Missing Values ]               |
                             |                         |
                             v                         |
              [ STEP 7: Apply Transformation ]         |
           (e.g. SMOTE Balancer / Median Imputer)      |
                             |                         |
                             v                         |
              [ STEP 8: Create New Version v002 ]      |
           (Original v001 is preserved untouched)      |
                             |                         |
                             v                         |
              [ STEP 9: Re-Evaluate on v002 ]          |
           (Calculate new Accuracy, Macro F1)          |
                             |                         |
                             v                         |
              [ STEP 10: Programmatic Comparison ]     |
           (Compute Delta: e.g. Macro F1: 71% -> 82%)  |
                             |                         |
                             v                         |
              [ STEP 11: Save Experiment to Memory ]   |
           (Store summary & deltas in ChromaDB)        |
                             |                         |
                             +------------+------------+
                                          |
                                          v
                    [ STEP 12: Compile Final Markdown Report ]
           (Generate single comprehensive .md report in storage/reports/)
                                          |
                                          v
                            [ FINISH & ANSWER USER ]

3. DETAILED DATA FLOW & LOGIC EXPLANATION
================================================================================

PHASE 1: MODEL & DATASET INGESTION (OR BENCHMARK PRESETS)
--------------------------------------------------------------------------------
- User can upload custom files OR select a 1-click preset (Iris, Breast Cancer, Wine).
- The pre-trained model is stored in: storage/models/<model_id>/
- The dataset is saved immutably in: storage/datasets/<dataset_id>/original/
- The initial version is established as: storage/datasets/<dataset_id>/versions/v001/dataset.csv

PHASE 2: DETERMINISTIC INSPECTION & VALIDATION
--------------------------------------------------------------------------------
- Model Inspector (app/models/inspector.py):
  Extracts framework (Sklearn, PyTorch, ONNX), input dimensions, parameter count.
- Dataset Inspector (app/datasets/inspector.py):
  Analyzes data types, missing values, duplicates, class ratios, IQR outliers.
- Compatibility Validator (app/datasets/validator.py):
  Validates that dataset feature count and classes match model requirements.

PHASE 3: DETERMINISTIC PYTHON EVALUATION ENGINE
--------------------------------------------------------------------------------
- Performance Evaluator (app/evaluation/performance.py):
  Pure Python calculation of Accuracy, Macro F1, Minority Class F1, Precision,
  Recall, Confusion Matrix, and ROC-AUC.
  *CRITICAL RULE*: The LLM NEVER guesses or invents numbers. All metrics are calculated by Python.
- Data Quality Evaluator (app/evaluation/data_quality.py):
  Measures exact imbalance ratios (e.g. 4.5:1) and missingness percentage.
- Robustness Evaluator (app/evaluation/robustness.py):
  Injects 10% Gaussian noise and measures degradation percentage.

PHASE 4: TRANSFORMATION & VERSIONING (DATA LEAKAGE SAFE)
--------------------------------------------------------------------------------
- When class imbalance is detected, the agent selects 'balance_data' (SMOTE).
- When missing values exist, the agent selects 'handle_missing_values'.
- When testing disturbance, the agent selects 'add_gaussian_noise'.
- A NEW IMMUTABLE VERSION IS CREATED:
  storage/datasets/<dataset_id>/versions/v002/
    ├── dataset.csv    (The transformed dataset)
    └── metadata.json  (Operation name, parameters, parent version)

PHASE 5: COMPARISON & CHROMADB SEMANTIC MEMORY
--------------------------------------------------------------------------------
- Comparison Engine (app/evaluation/comparison.py):
  Calculates exact metric deltas (e.g., Accuracy: 92% -> 90%, Macro F1: 71% -> 82%).
- ChromaDB Project Memory (app/memory/chroma_memory.py):
  Embeds the experiment summary and deltas into ChromaDB vector storage.
  Enables the user to ask in chat: "Did balancing help?" -> Agent retrieves stored result.

PHASE 6: SINGLE MARKDOWN REPORT GENERATION
--------------------------------------------------------------------------------
- Report Generator (app/reports/generator.py):
  Produces exactly 1 clean Markdown report stored at: storage/reports/<report_id>.md
  Contains: Baseline metrics, Data Quality Audit, Robustness, Transformations, 
  and LLM Diagnostic recommendations.

4. CODEBASE DIRECTORY & FILE MAPPING
================================================================================

app/
├── core/
│   ├── config.py         -> Environment settings (Ollama URL, Phi-3 model, ports)
│   ├── database.py       -> SQLite schema for authoritative project history
│   └── storage.py        -> Directory and file manager for models & datasets
│
├── models/
│   ├── adapters.py       -> Multi-framework adapters (Sklearn, PyTorch, ONNX)
│   ├── loader.py         -> Auto-detects model format and loads into memory
│   ├── inspector.py      -> Inspects architecture, shapes, parameters
│   ├── validator.py      -> Checks model integrity
│   └── predictor.py      -> Runs deterministic inference and predict_proba
│
├── datasets/
│   ├── loader.py         -> Loads CSV, Parquet, JSON into pandas
│   ├── inspector.py      -> Inspects rows, columns, missing values, class ratios
│   ├── profiler.py       -> Deep column-by-column statistical summary
│   ├── validator.py      -> Validates Model <-> Dataset feature compatibility
│   └── versioning.py     -> Manages immutable versions (v001, v002, metadata.json)
│
├── evaluation/
│   ├── performance.py    -> Objective metrics (Accuracy, F1 Macro/Minority, AUC)
│   ├── data_quality.py   -> Audits missingness, class imbalance, outliers
│   ├── robustness.py     -> Benchmarks performance drop under Gaussian noise
│   └── comparison.py     -> Programmatically compares before vs after metrics
│
├── transformations/
│   ├── cleaner.py        -> Missing value imputation (median/mean) & deduplication
│   ├── balancer.py       -> SMOTE and random oversampler for class imbalance
│   ├── scaler.py         -> Standard and MinMax normalization
│   ├── outliers.py       -> IQR outlier clipping and removal
│   └── noise.py          -> Gaussian noise, missingness, and label flipping
│
├── memory/
│   └── chroma_memory.py  -> ChromaDB vector database for semantic recall of experiments
│
├── agent/
│   ├── state.py          -> Explicit AgentState tracking variables, metrics, logs
│   ├── tools.py          -> Central Tool Registry defining the 15 deterministic tools
│   ├── planner.py        -> Decision engine (Ollama structured JSON + deterministic fallback)
│   └── agent.py          -> Closed-loop runner orchestrating the step-by-step cycle
│
├── services/
│   ├── project_service.py-> Project creation and file upload handlers
│   └── preset_service.py -> Automatic download & caching for Iris, Cancer, Wine benchmarks
│
├── reports/
│   └── generator.py      -> Compiles single clean Markdown (.md) evaluation report
│
├── api/                  -> FastAPI endpoints (/projects, /models, /chat, /presets, etc.)
└── main.py               -> App entrypoint serving REST API and Web Dashboard

frontend/
└── index.html            -> Interactive single-page dashboard with chat, presets, and metrics

storage/
├── models/               -> Uploaded / pre-trained model files
├── datasets/             -> Immutable version trees (original/, v001/, v002/...)
├── preset_downloads/     -> Cached Iris, Cancer, Wine datasets & models
├── reports/              -> Generated Markdown (.md) reports
└── chromadb/             -> Persistent ChromaDB vector embeddings

tests/
├── test_adapters_and_evaluators.py -> Unit tests for loaders, metrics, transformations
├── test_presets.py                 -> Tests for Iris benchmark loading & caching
└── test_e2e_workflow.py            -> Full autonomous end-to-end evaluation test
